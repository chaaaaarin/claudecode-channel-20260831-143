きっかけと、Anthropic の反論
anthropic.com/news — Redeploying Fable 5

"Amazon researchers had found a method of bypassing Fable 5's safeguards ... Our testing confirmed that many less capable models—including Claude Opus 4.8, GPT-5.5, and Kimi K2.7—could identify the same vulnerabilities as Fable 5 did in the report."

日本語訳：Amazon の研究者が Fable 5 の安全装置をすり抜ける方法を発見した（脆弱性を特定させ、1件は悪用コードまで出力）。だが検証の結果、Fable 5 より非力なモデル（Opus 4.8、GPT-5.5、Kimi K2.7 など）でも同じ脆弱性を特定できた。

  • 報告された手口を狙い撃ちする改良分類器で 99%超をブロック。ブロック分は Opus 4.8 に送られ通知される
  • 米商務省の AI 標準・イノベーションセンター（CAISI）が新旧の安全装置を検証し「非常に強力」と同意
  • 副作用：通常のコーディング・デバッグでも誤検知が増える（公式が明記）

③「Fableに聞いたのにOpusが返る」の正体

Fable 5 には拒否できる安全分類器が入っている（Mythos 5 には無い）。拒否されると別の Claude が肩代わりして答える——これが「フォールバック」。拒否は「エラー」ではなく通常の応答として返る。

画面で使っている場合
  • 回答の近くに「Opus 4.8 が応答しました」という趣旨の表示が出る（通知される設計）
  • まず「自分の質問がサイバー／生物・化学／競合AI開発に触れていないか」を振り返る
API・自作ツールの場合
# 拒否は HTTP 200 で、こう返る（公式ドキュメントより） { "model": "claude-fable-5", "stop_reason": "refusal", "stop_details": { "type": "refusal", "category": "cyber" } } # フォールバックが起きると応答に fallback ブロックが入り # 先頭の "model" が "claude-opus-4-8" に変わる
platform.claude.com/docs — Refusals and fallback

"You are not billed for a refusal that arrives before any output. ... Each attempt is billed separately, at the rates of the model that ran it."

日本語訳：出力が始まる前に拒否された分は課金されない。走った各試行はそのモデルの単価で個別に課金される（＝Opus が答えたぶんは Opus の料金）。

⚠️ それでも残る弱点

④ 8月の「頭が悪くなった」は本当か

言える（公式で確認）
  • 拒否 → Opus への切り替えという仕組みがある
  • 6月に停止し、7月に復旧した
  • 生物分野の誤検知は8月に約85%減った
  • 安全マージンを過去最大に振ったと公式が明言
言えない（裏づけなし）
  • 「Fable 5 の品質を意図的に下げた」という公式の言及
  • 「計算資源不足で弱体化」という説
  • 「次バージョンがもうすぐ出る」
「弱くなった？」と思ったら、この順で確認
  • 1フォールバックが起きていないか（応答のモデル名・切り替え通知を見る）
  • 2プロンプトと文脈：指示が曖昧になっていないか／会話が長すぎないか／effort（思考の深さ）設定
  • 3モデル世代：今つないでいるのは Fable 5 か、フォールバック先か
  • 4ここまでで説明がつかなければ、用途によって他モデルの併用を検討

この資料の立場：確認できるのはフォールバックの仕組みと公表された変更まで。「登場時と今で回答が変わったか」を外部から厳密に比べる方法は基本的になく、体感の差は数値化しにくい。

6

⑤ で、いま使うべきか（Claude Code での注意）

  • 長く複雑な自動タスク／大規模なコード変更→Fable 5 が向く
  • セキュリティ・生物・機械学習まわりが多い→フォールバック前提で。Opus 5 直指定も検討
  • 短い依頼・日常的なやりとり中心→無理に Fable でなくてよい
  • 安定した再現性が最優先→フォールバックの少ないモデルに固定する手も
長時間タスクを回すときに先に入れておくこと
  • 1フォールバックを最初から設定に入れる（`fallbacks: "default"` かSDKミドルウェア）
  • 2サブエージェントの呼び出しにも個別にフォールバックを設定（親の設定は引き継がれない）
  • 3refusal を専用ログとして記録し、「どのカテゴリで何回」を見えるようにする
  • 4再現性が要る検証では、応答の model 欄が途中で変わっていないか毎回確認
