## TL;DR（まず3行で）

1. **「Fable 5、前の全能感どこいった？」という不満の正体は、その大部分が "安全装置による別モデルへの切り替え（フォールバック）" で説明できる。** ✅

## 1. きっかけ：Xで広がった「まじでひどくないか？」

2026年8月20日、松丸 彗吾 氏（@k_matsumaru）のこの投稿が広がりました（表示 32.1万・いいね 683）。

> いやなんか Fable 5 まじでひどくないか？ 前の全能感どこいった？

返信欄でも「以前の能力が恋しい」「全知全能感がなくなった」「応答がかなり怪しくなってきた」という声が続きました。**これらはいずれも利用者個人の感想であり、裏づけのある事実ではありません。** ただ、「6月に華々しく登場したモデルが、なぜ2か月で『弱くなった』と言われているのか」は、経緯を追うと整理できます。

「大炎上」は、この4つが積み重なった総称です。以下、①②③④の順に見ていきます。

## 3. ① なぜ最強なのに使いにくいのか（安全装置の作り）

### 登場時に語られた「最強」の中身（すべて Anthropic が公表した実例）

- **5000万行の Ruby コードの一括移行を、チームで2か月かかる作業を1日で完了**（Stripe の報告）✅
- **ある分析タスクのベンチマークで初めて 90% を超え、Opus 比で +10 点**（導入企業の報告）✅
- **物理研究で、GPT-5.5 が4日かけた地点に36時間で到達**（導入企業の報告）✅

出典：[Claude Fable 5 and Claude Mythos 5（Anthropic 公式発表）](https://www.anthropic.com/news/claude-fable-5-mythos-5)

### そのぶん、安全装置を「過去最大」に振った

Anthropic は再展開の声明で、こう書いています（原文の要旨）：

> Fable 5 では、この「安全マージン」を過去のどのリリースよりも大きく取った。つまり、無害なリクエストもより多くブロックされる。利用者にとって迷惑（誤検知）だと分かっていたが、他の能力を広く使えるようにするためにこのトレードオフを選んだ。 ✅

出典：[Redeploying Fable 5（Anthropic 公式声明）](https://www.anthropic.com/news/redeploying-fable-5)

### 止められる領域は、公式が3つ挙げている

| 領域 | 中身 | 巻き込まれる正当な作業 |
|---|---|---|
| サイバー | 脆弱性の発見・攻撃コードなど | 善良なセキュリティ業務 |
| 生物・化学 | 危険な実験手法など | 正当な生命科学の研究 |
| 蒸留（distillation） | 競合 AI モデルの開発を助けるリクエスト | ふつうの機械学習の作業 |

「蒸留」とは、Claude の能力を吸い出して競合モデルの学習に使う試みのこと。開発者向けドキュメントでは、この判定カテゴリは **`frontier_llm`** という名前で返ります（「ふつうの機械学習の作業でも発火しうる」と明記）。🔶

引っかかると、応答は自動的に **Claude Opus 4.8** が肩代わりし、**その旨がユーザーに通知されます**（登場時からの仕様）。発動するのはセッションの **5% 未満**（平均・登場時点）で、95% 超のセッションではフォールバックは一度も起きない、とされています。✅

### この設計のデメリット（公式も認めている）

- 「明らかに安全」と判定されないと通さない設計。**善良なセキュリティ業務・生命科学・機械学習でも発動しうる**。⚠️
- 安全マージンを過去最大に振ったぶん、無害なリクエストのブロックも増える（公式が明言）。⚠️
- Anthropic は「誤検知は減らしていく」としているが、ゼロにはならない。⚠️

## 4. ② なぜ米政府に止められ、なぜ今使えるのか

### 時系列 ✅

- **6/9（火）** Fable 5 / Mythos 5 公開
- **6/12（金）** 米政府が輸出管理を適用。「外国籍の利用者に制限を」という指示が即時発効し、国籍確認ができないため**全ユーザーのアクセスを停止**。冒頭の更新で「お客様にご迷惑をおかけして申し訳ありません」
- **6/26** 一部の米組織向けに Mythos 5 を承認
- **6/30** 輸出管理が解除
- **7/1（水）** Fable 5 を世界的に再開（7/7 まで週次上限の最大50%まで無料、以降は従量課金）

### きっかけと、Anthropic の反論

Amazon の研究者が Fable 5 の安全装置をすり抜ける方法を発見しました。うまく指示すると脆弱性をいくつも特定させられ、1件は悪用コードまで出力させたとのこと。ただし Anthropic の検証では、

> Fable 5 より非力なモデル（Claude Opus 4.8、GPT-5.5、Kimi K2.7 など）でも、報告と同じ脆弱性を特定できた ✅

とされ、「これは Mythos 級だけの特別な能力ではなく、日常的な防御セキュリティ作業の範囲」という立場をとっています。対応として、

- 報告された手口を狙い撃ちする改良分類器で **99% 超をブロック**。ブロック分は Opus 4.8 に送られ通知される ✅
- 米商務省の AI 標準・イノベーションセンター（CAISI）が新旧の安全装置を検証し「非常に強力」と同意 ✅
- 副作用：通常のコーディング・デバッグでも誤検知が増える（公式が明記）⚠️

出典：[Redeploying Fable 5（Anthropic 公式声明）](https://www.anthropic.com/news/redeploying-fable-5) ／ [Statement on the US government directive（Anthropic 公式声明）](https://www.anthropic.com/news/fable-mythos-access)

> **なお：** 一部の報道は「Anthropic が競合 AI 開発者向けに黙って応答を劣化させ、その判断を誤ったと謝罪した」という趣旨で伝えています。しかし Anthropic の**公式ページ上で確認できるのは、上記の "通知あり・Opus へフォールバック" という現在の仕様と、アクセス停止に対する「お客様にご迷惑を〜」の一文まで**です。この資料では、公式で確認できた範囲だけを扱います。

## 5. ③「Fableに聞いたのにOpusが返る」の正体

Fable 5 には拒否できる安全分類器が入っています（Mythos 5 には無い）。拒否されると別の Claude が肩代わりして答える——これが「フォールバック」です。**拒否は「エラー」ではなく通常の応答として返る**のがポイント。

### 画面で使っている場合

- 回答の近くに「**Opus 4.8 が応答しました**」という趣旨の表示が出る（通知される設計）
- 急に応答の毛色が変わった → まず「自分の質問がサイバー／生物・化学／競合 AI 開発に触れていないか」を振り返る

### API・自作ツールの場合

拒否は HTTP 200 で、こう返ります（公式ドキュメントより）：

```json
{
  "model": "claude-fable-5",
  "stop_reason": "refusal",
  "stop_details": { "type": "refusal", "category": "cyber" }
}
```

フォールバックが起きると応答に `fallback` ブロックが入り、先頭の `model` が `claude-opus-4-8` に変わります。**拒否は 200 で返るのでエラー率では見えません。** `refusal` を専用のシグナルとして記録するのがコツです。

### 課金は？

> 出力が始まる前に拒否された分は課金されない。走った各試行はそのモデルの単価で個別に課金される（＝Opus が答えたぶんは Opus の料金） ✅

出典：[Refusals and fallback（Claude 公式ドキュメント）](https://platform.claude.com/docs/en/build-with-claude/refusals-and-fallback)

### 誤検知は減ってきている（生物分野・8月7日）✅

- 生物関連のフォールバック：**全サーフェス平均で約85%減**
- 内訳：Claude.ai 約67%減 ／ Claude Cowork 約55%減 ／ Claude Code 約17%減

出典：[Improving Fable 5's biology safeguards（Anthropic 公式発表）](https://www.anthropic.com/news/improving-fable-5-s-biology-safeguards)

### それでも残る弱点 ⚠️

- 改善しても誤検知はゼロにならない（通常のコーディングでも起きうると公式が明記）
- フォールバック先のモデル名は**時期で変わる**（6月は Opus 4.8、以降のドキュメントでは Opus 5 も併記）
- いちど切り替わった会話は、以後も切り替え先モデルに固定されることがある（sticky routing）

## 6. ④ 8月の「頭が悪くなった」は本当か

### 一次情報で「言えること」と「言えないこと」

| 言える（公式で確認）✅ | 言えない（裏づけなし）⚠️ |
|---|---|
| 拒否 → Opus への切り替えという仕組みがある | 「Fable 5 の品質を意図的に下げた」という公式の言及 |
| 6月に停止し、7月に復旧した | 「計算資源不足で弱体化」という説 |
| 生物分野の誤検知は8月に約85%減った | 「次バージョンがもうすぐ出る」 |
| 安全マージンを過去最大に振ったと公式が明言 | |

### 「弱くなった？」と思ったら、この順で確認

1. **フォールバックが起きていないか** — 応答のモデル名・切り替え通知を見る
2. **プロンプトと文脈** — 指示が曖昧になっていないか／会話が長くなりすぎていないか／effort（思考の深さ）設定
3. **モデル世代** — 今つないでいるのは Fable 5 か、フォールバック先（Opus 4.8 / Opus 5）か
4. ここまでで説明がつかなければ、**用途によって他モデルの併用を検討**

### 正直に言うと、ここは限界があります

「登場時と今で回答が変わったか」を、外部から厳密に比べる方法は基本的にありません。Anthropic はモデルを予告なく微調整することがあり（各社共通）、それが「劣化」と感じられることもあります。**この資料の立場は「確認できるのはフォールバックの仕組みと公表された変更まで。弱くした／していないは断定しない」です。**

## 7. ⑤ で、いま使うべきか（Claude Code での注意）

| 用途 | 目安 |
|---|---|
| 長く複雑な自動タスク／大規模なコード変更 | Fable 5 が向く（得意分野）|
| セキュリティ・生物・機械学習まわりが多い | フォールバック前提で。Opus 5 直指定も検討 |
| 短い依頼・日常的なやりとり中心 | 無理に Fable でなくてよい（コスト面も）|
| 安定した再現性が最優先 | フォールバックの少ないモデルに固定する手も |

（用途への当てはめは本資料の整理です。最終判断は自分の環境で試して決めてください。）

### 長時間タスクを回すときに先に入れておくこと

1. フォールバックを最初から設定に入れる（`fallbacks: "default"` か SDK ミドルウェア）。拒否で処理が止まらないように
2. サブエージェントの呼び出しにも個別にフォールバックを設定する（親の設定は引き継がれない）
3. `refusal` を専用ログとして記録し、「どのカテゴリで何回」起きたかを見えるようにする
4. 再現性が要る検証では、応答の `model` 欄が途中で変わっていないか毎回確認する

出典：[Refusals and fallback（Claude 公式ドキュメント）](https://platform.claude.com/docs/en/build-with-claude/refusals-and-fallback)

## 8. メリット・デメリット総まとめ

| 観点 | メリット | デメリット・注意 |
|---|---|---|
| 能力 | 長く複雑なタスクで過去最強クラス | 無料枠では使いづらい時期がある |
| 安全装置 | 危険用途を止める・切り替えは通知される | 正当な作業も誤検知で止まりうる |
| フォールバック | 拒否でも答えが返る／出力前拒否は無課金 | Fable のつもりが Opus になる・時期で先が変わる |
| 「劣化」の声 | 仕組みは説明可能・切り分けできる | 体感の差は数値で確認できない |

## 今日からやること（始めるならこの順番）

1. いま使っている Claude の応答に「別モデルに切り替えました」表示がないか一度見る
2. API・自作ツールを使っているなら `stop_reason: "refusal"` の検知とフォールバック設定を入れる
3. 「弱くなった？」と思ったら、切り分けチェックリストの順で確認する
4. 用途ごとに Fable 5 / Opus 5 の向き不向きを一度メモにしておく

## まとめ

- 「弱くなった」の多くは、安全装置による Opus への切り替え（フォールバック）
- 切り替えは通知される。API なら `refusal` で検知できる
- 体感の劣化そのものは一次情報では断定できない。まず切り分け
- Claude Code で回すなら、フォールバック設定と `refusal` 監視を先に

## 動画内で補足する用語

| 用語 | かみ砕き |
|---|---|
| フォールバック | 本命のモデルが断ったとき、別のモデルに自動で回して答えさせる仕組み |
| セーフティ分類器 | 入力が危険な用途かを判定して拒否するフィルタ。Fable 5 に内蔵、Mythos 5 には無い |
| `stop_reason: "refusal"` | API の応答で「安全装置が拒否した」ことを示す値。エラーではなく通常の応答として返る |
| 蒸留（distillation） | あるモデルの出力を大量に集めて、別（競合）のモデルを学習させること |
| システムカード | モデルの能力・危険性の評価をまとめた公式の技術文書 |
| Mythos（ミュトス）5 | Fable 5 と中身は同じで、安全装置を一部外した版。限定提供で一般ユーザーは使えない |
| effort（エフォート） | モデルにどれだけ深く考えさせるかの設定。深いほど遅く高価になりやすい |
| dual-use（デュアルユース） | 善用にも悪用にもなりうる能力・情報のこと（例：脆弱性の知識） |
